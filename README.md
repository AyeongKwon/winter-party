# 🥞 호떡 만들기

밀려드는 손님에게 호떡을 구워 파는 모바일 웹 게임입니다.
빌드 과정 없이 HTML, CSS, JavaScript만으로 동작합니다.

## 게임 규칙

- 호떡 1개 = 2,000원 (점수)
- 손님은 호떡을 1~5개 주문합니다.
- 손님의 인내심이 다 떨어지면 하트가 1개 줄어듭니다. 하트 3개가 모두 없어지면 게임 오버입니다.
- 시간이 지날수록 손님이 더 자주, 더 많이 주문합니다.

## 조작 방법

1. **젓기**: 볼을 빙글빙글 문지르면 반죽이 접시에 올라갑니다. (접시에는 3개까지)
2. **만지기**: 반죽을 문질러 동그랗게 만듭니다.
3. **올리기**: 철판의 빈 칸을 누르면 동그란 반죽이 올라갑니다.
4. **누르기**: 반죽을 꾹 누르고 있다가 게이지가 초록 구간일 때 손을 뗍니다. 너무 오래 누르면 시럽이 터져서 실패합니다.
5. **뒤집기**: 노릇해지면 눌러서 뒤집고, 다시 노릇해지면 눌러서 꺼냅니다. 너무 오래 두면 타서 실패합니다.
6. **서빙**: 손님을 누르면 완성된 호떡을 건넵니다. 주문 개수를 다 채우면 돈을 받습니다.

실패한 호떡은 철판 칸을 눌러 버립니다.

## 실행하기

`index.html`을 브라우저에서 열면 바로 실행됩니다.

휴대폰으로 테스트하려면 같은 와이파이에서 간단한 서버를 띄우면 편합니다.

```bash
# 프로젝트 폴더에서
python3 -m http.server 8000
# 휴대폰 브라우저에서 http://<컴퓨터 IP>:8000 접속
```

## GitHub Pages로 배포하기

1. 이 폴더를 GitHub 저장소에 올립니다.
2. 저장소의 **Settings → Pages**로 갑니다.
3. **Source**를 `Deploy from a branch`, 브랜치를 `main`, 폴더를 `/ (root)`로 선택하고 저장합니다.
4. 1~2분 뒤 `https://<아이디>.github.io/<저장소 이름>/`에서 게임이 열립니다.

## 폴더 구조

```
hotteok-game/
├── index.html        화면 구조
├── css/style.css     디자인 (393×852 기준, 기기 크기에 맞춰 자동 확대·축소)
├── js/config.js      밸런스 숫자 모음 (난이도 조정은 여기서)
├── js/logic.js       게임 규칙과 상태 (화면 코드 없음)
├── js/assets.js      이미지 파일 목록
├── js/ui.js          화면 그리기와 터치 입력
└── assets/           디자인 이미지 (assets/README.md 참고)
```

## 역할별로 보는 파일

| 담당 | 파일 |
|---|---|
| 디자인 | `assets/` 폴더에 정해진 파일명으로 이미지 넣기, `css/style.css` 색상 |
| 프론트엔드 | `index.html`, `css/style.css`, `js/ui.js` |
| 로직 / 밸런스 | `js/config.js`, `js/logic.js` |

## 난이도 조정

`js/config.js`의 숫자만 바꾸면 됩니다. 자주 만질 값은 이렇습니다.

| 값 | 의미 | 기본값 |
|---|---|---|
| `patienceBase`, `patiencePerItem` | 손님 인내심 (기본 + 개수당) | 10초 + 7초 |
| `spawnIntervalStart`, `spawnIntervalMin` | 손님 등장 간격 (처음 → 최소) | 12초 → 5초 |
| `orderWeights` | 시간대별 주문 개수 확률 | 초반 1~2개 → 후반 1~5개 |
| `stirDistancePerDough` | 반죽 1개를 만드는 데 필요한 젓기 양 | 800 |
| `pressGoodMin`, `pressBurst` | 누르기 성공 구간 / 시럽 터짐 | 0.55 / 1.0 |
| `cookRateA`, `cookRateB`, `cookBurnt` | 굽는 속도 / 타는 지점 | 3초, 2.5초 / 1.5 |

최고 점수는 브라우저에만 저장됩니다. (서버 없음)
